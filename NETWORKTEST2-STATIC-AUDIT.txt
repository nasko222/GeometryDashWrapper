Root cause addressed:
- NetworkTest bounded guest ARM execution, but not time spent inside a host import.
- The log ended immediately after worker slice #2 began, before the old post-call
  DNS diagnostic. A synchronous WinSock resolver call on the UI thread could
  therefore freeze the entire window indefinitely.
- NetworkTest2 performs resolver work on detached native threads and leaves the
  guest worker parked on its import stub. The main frame pump wakes it only after
  completion or the 8-second resolver timeout.

- current v22 beta APK supplied to the builder
- existing desktop keyboard-pan suppression retained
- existing local save-v22beta redirection retained
- editor/companion feature experiments are not the focus of this branch

Limitations:
- no Windows cross-link or live network test was possible in this environment
- the Linux syntax pass does not compile _WIN32-only WinSock code
