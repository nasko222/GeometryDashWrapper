NETWORKTEST5 ROOT CAUSE
=======================

Observed in both supplied NetworkTest4 logs:

1. CCHttpClient creates worker entry 0x1046514d.
2. The request signal starts worker slice 1.
3. Frame pumping starts slice 2.
4. Frame pumping starts slice 3 and never returns.
5. The saved worker PC/LR is in the libc memset trampoline returning to
   OpenSSL CRYPTO_zalloc (ELF +0x6c5f54).
6. No getaddrinfo/gethostbyname/socket/connect/send/recv call occurs first.
7. No worker watchdog completion line is emitted.

Therefore the failure is not DNS, GDPS reachability, or the APK icon. It is the
NetworkTest2-4 worker execution model: suspending and resuming the ARM HTTP
worker at arbitrary import boundaries during OpenSSL initialization.

NetworkTest5 removes slicing and restores the known-working DynarmicTest14
run-to-wait model. The beta uses pthread condition variables rather than the
older semaphore path, so condition signal/broadcast are treated as Dyn14's
sem_post wake: resume immediately and execute continuously until wait/exit.
