JULY 30 UPLOADED-LOG DIAGNOSIS

1. Legacy ARM attempt volume
- Geometry Dash 1.0 and 1.4 both call preloadBackgroundMusic before their
  initial setBackgroundMusicVolume call.
- Later, opening a level track creates a different MCI alias. EnduranceTest6
  automatically copied the stored Android volume into every new alias, while
  MCI restart behavior returned to the device volume after the first attempt.
- EnduranceTest7 removes the frame guard and every play/resume/seek reassert.
  It also sends no stored-volume command merely because a new alias opened.
- A live setBackgroundMusicVolume call still changes the currently open alias.

2. Selected 2.2 beta BPM markers
- The editor session reset occurs and DrawGridLayer is found before overlay
  frame 1; the song guide update also runs at frame 1.
- No successful time-marker rebuild is logged in the EnduranceTest6 run.
- EnduranceTest7 invokes DrawGridLayer::updateTimeMarkers exactly once at frame
  1 of each newly created editor session. It is never periodic and the host
  never calls LevelEditorLayer::updateGridLayer.

3. Selected 2.2 beta black moving region
- EnduranceTest6 camera culling and client-array/VBO repair remain active and
  no other editor regressions were reported in the July 30 test.
- The exact 636-byte LevelEditorLayerExt::updateVisibilityH companion helper
  does not force every visible object to opacity 255. It uses object fields
  +0x4AF, +0x236, +0x405, editor field +0x2C50, object group fields +0x450 and
  +0x454, and GameManager variable "0121" to choose opacity 0, 70 or 255.
- EnduranceTest6 forced activated objects fully opaque. EnduranceTest7 follows
  the exact helper's opacity policy while retaining the fast host camera walk.
